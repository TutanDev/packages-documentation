IMessage / IEvent / ICommand

Marker interfaces in Tutan.Messages (assembly Tutan.Messages). A message is a struct implementing IEvent or ICommand.

IMessage interface
marker
interface IMessage
Base marker for every message struct. Not used directly: implement IEvent or ICommand instead.
IEvent interface
marker
interface IEvent : IMessage
Notification: any number of handlers may subscribe via EventBus. Name it in the past tense (PlayerScored).
ICommand interface
marker
interface ICommand : IMessage
Intent: at most one handler, declared at the composition root via CommandBus.Install. Name it in the imperative (MovePlayer).

MessageHandler<T>

Delegate type in Tutan.Messages.

MessageHandler<T> delegate
sig
void MessageHandler<T>(ref T message) where T : struct, IMessage
Receives the message by ref, so there is no copy per handler. A handler may mutate it, and later handlers in the same dispatch (registration order) see the change.

EventBus

Static N:M facade in Tutan.Messages. The dispatch methods (Publish, Enqueue, DrainQueues) are identical across EventBus, CommandBus, and the underlying MessageBus<TBase> they wrap; the buses differ only in how handlers are registered. On EventBus, T is constrained to struct, IEvent.

EventBus static
method
Subscription Subscribe<T>(MessageHandler<T> handler) where T : struct, IEvent
Registers handler for messages of type T. Returns a disposable Subscription; disposing it is how you unsubscribe. Throws ArgumentNullException for a null handler. Main thread only. EventBus only: commands bind through CommandBus.Install.
method
void Publish<T>(ref T message) where T : struct, IEvent
Dispatches synchronously to all active subscribers of T, in registration order. Zero-copy. Main thread only. If no channel exists for T (nothing has subscribed to or enqueued T since the last reset), returns after one dictionary lookup; otherwise it walks the channel's entry list, even if no handler is active any more.
method
void Publish<T>(T message) where T : struct, IEvent
Convenience overload that copies once (caller to parameter). Acceptable for small messages when the ref call site is inconvenient.
method
void Enqueue<T>(in T message) where T : struct, IEvent
Copies message into the per-type queue for T. Thread-safe via ConcurrentDictionary + ConcurrentQueue: safe to race with main-thread Subscribe/Publish/DrainQueues and with concurrent Enqueue calls from other worker threads (channel creation goes through GetOrAdd; the per-channel queue's lazy creation is a compare-and-swap). Dispatched on the next DrainQueues(). The first Enqueue of a type allocates its channel and queue.
method
void DrainQueues()
Dispatches the queued messages of every channel on the bus. Each channel's drain is bounded by what was queued when it started: a handler that enqueues its own type extends the next drain, not this one. Call once per frame, main thread only. By default MessagesHost does this for you.
method
int GetSubscriberCount<T>() where T : struct, IEvent
Active subscriptions (handlers) for T.
prop
int ChannelCount { get; }
Message types subscribed to or enqueued since the last reset.
method
void Reset()
Clears all subscriptions and queues; use on test teardown. Disposes the current bus instance and swaps in a fresh one: outstanding Subscription handles become no-ops, and queued messages are discarded, not dispatched. Both buses also reset themselves on every Enter Play Mode (at SubsystemRegistration), so state never leaks between play sessions when Domain Reload is disabled.

Subscription / SubscriptionBag

Subscription lifetime types in Tutan.Messages. Subscribe returns a Subscription: a disposable struct pairing the subscription's identity with the bus instance that issued it. Disposing it is the only way to unsubscribe; there is no -=. Hold it and dispose explicitly, collect several in a SubscriptionBag, or tie it to a GameObject's lifetime with .AddTo(this). Subscription is a struct around an id plus an existing reference, so Subscribe allocates nothing per call beyond occasional growth of the type's subscriber list; the first Subscribe of a type also allocates its channel.

Subscription struct
prop
bool IsActive { get; }
false once this handle has been disposed (or was never issued). Disposing a copy also unsubscribes, but only the copy you disposed through reports IsActive == false.
method
void Dispose()
Unsubscribes. Idempotent, main thread only, and safe during dispatch (the handler is marked inactive and skipped for the remainder of the current dispatch cycle). Because the handle captures the bus instance, disposing a Subscription taken before a Reset() is a no-op: it can never remove an unrelated subscription on the replacement bus.
SubscriptionBag class
prop
int Count { get; }
Subscriptions currently held.
method
void Add(Subscription subscription)
Adds a subscription to the bag. Inactive handles are ignored. The bag's list grows as you add to it.
method
void Clear()
Disposes every held subscription and empties the bag.
method
void Dispose()
Same as Clear(); the bag stays usable afterwards, so one bag per system replaces one handle field per subscription.
SubscriptionExtensions static
method
Subscription AddTo(this Subscription s, SubscriptionBag bag)
Adds the subscription to a SubscriptionBag; the bag's Dispose() releases it.
method
Subscription AddTo(this Subscription s, GameObject gameObject)
Ties the subscription to the GameObject's lifetime: disposal happens in OnDestroy via one hidden SubscriptionAnchor component per GameObject. The common MonoBehaviour pattern collapses to EventBus.Subscribe<PlayerMoved>(OnMoved).AddTo(this); with no handle field and no OnDestroy.
method
Subscription AddTo(this Subscription s, Component component)
Same, for the component's GameObject.
SubscriptionAnchor class
type
sealed class SubscriptionAnchor : MonoBehaviour
Added by AddTo(GameObject); never add it by hand. Hidden in the Inspector, never saved into a scene or prefab, and [ExecuteAlways], so destroying its GameObject disposes the subscriptions in edit mode too. A GameObject destroyed without ever having been active never runs OnDestroy, so its subscriptions are not disposed: hold the Subscription or use a bag for pooled or disabled instances.

CommandBus

Static N:1 facade in Tutan.Messages. Shares Publish, Enqueue, DrainQueues, Reset, GetSubscriberCount<T>, and ChannelCount with EventBus, with T constrained to struct, ICommand. It has no Subscribe: each command type has at most one handler, declared once at the composition root via Install.

CommandBus static
method
InstallResult Install(Action<CommandRegistry> configure)
Declares every command handler in one place. On success the new bindings are swapped in atomically. On a duplicate command type, a null handler, or a null configure the live bus is left untouched and the failure is reported in the result, never as an exception. Calling it again rebuilds the bus from scratch (composition-root semantics).
method
void Publish<T>(ref T message) / void Publish<T>(T message)
Dispatches the command to its handler. Publishing a command with no handler is a silent no-op.
method
void Enqueue<T>(in T message) / void DrainQueues() / void Reset()
Same semantics as EventBus.
method
int GetSubscriberCount<T>() where T : struct, ICommand
0 or 1. For commands that must be handled, assert CommandBus.GetSubscriberCount<T>() == 1 once after Install.
prop
int ChannelCount { get; }
Message types subscribed to or enqueued since the last reset.
InstallResult struct
prop
bool Ok { get; }
true when the bindings were validated and swapped in.
prop
string Error { get; }
Names the offending command type(s); null when Ok.
prop
int HandlerCount { get; }
Number of handlers bound; 0 on failure.
CommandRegistry class
method
CommandRegistry Handle<T>(MessageHandler<T> handler) where T : struct, ICommand
Fluent builder, available only inside the Install callback (it cannot be constructed directly). Binds the handler for command type T; chain one Handle<T> per command.
Install before anything enqueues Like Reset, a successful Install replaces the bus, so any commands still queued for the next drain are discarded - including on the first install. The editor and development builds log a warning naming the discarded types. Install from a BeforeSceneLoad [RuntimeInitializeOnLoadMethod], or from a bootstrap object with an early Script Execution Order (plain Awake order between objects is undefined). For multi-app builds that vary by feature set or backend, select which handlers to bind and which backend to inject into them at the composition root, then funnel them all through one Install.

MessageBus<TBase>

class MessageBus<TBase> : IDisposable where TBase : IMessage in Tutan.Messages. The engine behind both facades. A standalone instance is not drained by MessagesHost - call its DrainQueues() yourself. MessageBus<ICommand> used directly does not enforce the N:1 rule; only CommandBus.Install does. Its instrumentation records are tagged BusKind.Command when TBase is or derives from ICommand, and BusKind.Event otherwise.

MessagesHost / MessagesBootstrap

The host is auto-spawned (hidden, DontDestroyOnLoad) at BeforeSceneLoad unless TUTAN_MESSAGES_NO_AUTO_HOST is defined. With the define set, attach MessagesHost to a persistent GameObject yourself or drain from your own loop; see Auto-bootstrap.

MessagesHost class
type
[AddComponentMenu("Tutan/Messages Host")] sealed class MessagesHost : MonoBehaviour
Each LateUpdate it calls MessagesInstrumentation.SyncFrame, then CommandBus.DrainQueues(), then EventBus.DrainQueues(). A second active host destroys itself with a warning.
MessagesBootstrap static
type
static class MessagesBootstrap
Spawns the host at startup. No public members. Command handlers are bound explicitly at your composition root via CommandBus.Install; there is no reflection-based auto-install.

Serialized References

Runtime types in Tutan.Messages that let designers pick a message type and edit its payload from the Inspector. They work in player builds, but not on hot paths: publishing involves JSON deserialization, Activator.CreateInstance, and boxing the struct before it is dispatched through the non-generic PublishBoxed seam (one unbox inside the channel). Message structs authored through a reference must be marked [Serializable]: the payload round-trips through JsonUtility, and a struct without the attribute silently keeps its default values.

string TypeName { get; }
Stored AssemblyQualifiedName; empty when none is picked.
prop
bool IsValid { get; }
A type has been picked (it may still fail to resolve).
method
Type GetMessageType()
Drift-tolerant type lookup; null if unresolvable. Same resolution as MessageTypeResolver.
method
object CreateMessage()
Boxed struct built from the stored JSON payload; default values on bad JSON.
method
abstract void Publish()
Synthesizes the message and dispatches it. Boxes and parses JSON: authoring and debug use, not hot paths. On a reference whose type no longer resolves, logs a warning and publishes nothing.
EventReference / CommandReference class
type
[Serializable] class EventReference : MessageReference
Publish() dispatches through EventBus. The Inspector dropdown lists IEvent structs.
type
[Serializable] class CommandReference : MessageReference
Publish() dispatches through CommandBus. The Inspector dropdown lists ICommand structs.

The inline editor renders each field with its matching native UI-Toolkit control: int, long, float, double, bool, string, any enum, Vector2/Vector3/Vector4, Vector2Int/Vector3Int, Color, and Quaternion (edited as euler angles). Other types fall back to a disabled "unsupported type" label. Every field is authored explicitly, including a field named Timestamp: the reference publishes exactly the values you enter, with nothing populated implicitly at publish time. See Editor Tooling.

[EventType] / [CommandType] / MessageTypeResolver

Runtime types in Tutan.Messages. The attributes decorate a string field so the Inspector renders it as a dropdown of message structs, storing the selected AssemblyQualifiedName; MessageTypeResolver turns that string back into a Type.

EventTypeAttribute attribute
usage
[EventType] public string eventType;
Dropdown of all concrete IEvent structs in loaded assemblies. A PropertyAttribute exposing Type BaseType { get; }.
CommandTypeAttribute attribute
usage
[CommandType] public string commandType;
Dropdown of all concrete ICommand structs in loaded assemblies. A PropertyAttribute exposing Type BaseType { get; }.
MessageTypeResolver static
method
static Type Resolve(string typeName)
Assembly-qualified or full name to Type; null if not found, never throws. Unlike a bare Type.GetType, it survives an assembly rename (e.g. the script moved into or out of an .asmdef) by falling back to the namespace-qualified name in every loaded assembly. Resolve once at load time, not per frame: the fallback path scans loaded assemblies.

Only structs appear in the dropdowns (the bus is constrained to where T : struct), and open generic structs are not listed, since without type arguments they can't be published.

MessagesInstrumentation

Static diagnostics surface in Tutan.Messages, read by the Messages Console and available to your own overlays or telemetry. Records exist only where the hooks are compiled in: the editor, or a player built with TUTAN_MESSAGES_DEBUG. The hooks are [Conditional("UNITY_EDITOR")] / [Conditional("TUTAN_MESSAGES_DEBUG")], so in a release player they are stripped, Enabled = true is a silent no-op, and the ring buffer is never allocated.
