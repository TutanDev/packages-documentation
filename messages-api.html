IMessage / IEvent / ICommand

Marker interfaces in Tutan.Messages. Implementing types must be a struct.

IMessage interface
marker
interface IMessage
Root marker interface. Not used directly — implement IEvent or ICommand instead.
IEvent interface
marker

Marker for N:M notifications. Any number of subscribers may register via EventBus. Name in past tense.

Marker for N:1 intents. Exactly one handler is bound per command type, declared at the composition root via CommandBus.Install. Name in imperative.

EventBus

Static N:M facade in Tutan.Messages.

EventBus static
method
Subscription Subscribe<T>(MessageHandler<T> handler) where T : struct, IEvent
Registers a handler. Returns a disposable Subscription — disposing it is how you unsubscribe. Main thread only.
method
void Publish<T>(ref T message) where T : struct, IEvent
Dispatches immediately to all subscribers on the calling thread. Zero-copy via ref. Main thread only.
method
void Publish<T>(T message) where T : struct, IEvent
Convenience overload — one struct copy from caller to parameter. Acceptable for small messages where the ref call site is inconvenient.
method
void Enqueue<T>(in T message) where T : struct, IEvent
Thread-safe enqueue. Channel lookup/creation goes through ConcurrentDictionary.GetOrAdd, the per-channel pending queue is lazily created with a compare-and-swap, and the message lands in a ConcurrentQueue<T>. Safe to race with main-thread calls and with concurrent Enqueue calls from other worker threads. Dispatched on the next DrainQueues().
method
void DrainQueues()
Processes all pending queued messages across all channels. Call once per frame on the main thread. MessagesHost does this in LateUpdate by default.
method
int GetSubscriberCount<T>() where T : struct, IEvent
Number of active subscribers for message type T.
prop
int ChannelCount { get; }
Number of distinct message types with at least one active subscriber.
method
void Reset()
Clears all subscriptions and queues. Use on test teardown.

CommandBus

Static N:1 facade in Tutan.Messages. Shares Publish, Enqueue, DrainQueues, and Reset with EventBus, but has no Subscribe: the single handler per ICommand type is declared once at the composition root via Install.

CommandBus static
method
InstallResult Install(Action<CommandRegistry> configure)
Declares every command handler in one place. On success the new bindings are swapped in atomically. On a duplicate command type or a null handler the live bus is left untouched and the failure is reported in the result — never as an exception. Calling it again rebuilds the bus from scratch (composition-root semantics).
struct
readonly struct InstallResult { bool Ok; string Error; int HandlerCount; }
Returned by Install. Ok is true when the bindings were validated and swapped in; Error names the offending command type(s) (null when Ok); HandlerCount is the number of handlers bound (0 on failure).
method
CommandRegistry Handle<T>(MessageHandler<T> handler) where T : struct, ICommand
Fluent builder method, available inside the Install callback. Binds the single handler for command type T. Chain one Handle<T> per command.
method
void Publish<T>(ref T command) / void Publish<T>(T command)
Dispatches the command to its single handler. No-op if no handler is registered.
method
void Enqueue<T>(in T command) / void DrainQueues() / void Reset()
Same semantics as EventBus.

Subscription / SubscriptionBag

Subscription lifetime types in Tutan.Messages. Subscribe returns a Subscription — a disposable struct pairing the subscription's identity with the bus instance that issued it. Disposing it is the only mechanism for unsubscription — no -= operator. Hold it and dispose explicitly, collect several in a SubscriptionBag, or tie it to a GameObject's lifetime with .AddTo(...).

Subscription struct
method
void Dispose()
Unsubscribes the handler. Idempotent, safe to call during dispatch (the handler is marked inactive and skipped for the remainder of the current dispatch cycle), and a harmless no-op after the issuing bus was Reset() — it can never remove an unrelated subscription from the replacement bus. Main thread only. Zero allocation: Subscription is a struct around an id plus an existing reference, so Subscribe allocates nothing beyond the handler entry itself.
SubscriptionBag class
method
void Dispose() / void Clear()
Disposes every subscription added to the bag as a group. The bag is reusable after disposal — one bag per system instead of one handle field per subscription.
AddTo extensions static
method
Subscription AddTo(this Subscription, SubscriptionBag bag)
Adds the subscription to a SubscriptionBag; the bag's Dispose() releases it.
method
Subscription AddTo(this Subscription, GameObject gameObject) / AddTo(this Subscription, Component component)
Ties the subscription to a GameObject's lifetime: one hidden SubscriptionAnchor component is attached per GameObject and disposes its bag in OnDestroy. The common MonoBehaviour pattern collapses to EventBus.Subscribe<PlayerMoved>(OnMoved).AddTo(this); — no handle field, no OnDestroy override. The bag and the anchor component each allocate once at creation.

MessagesHost

MonoBehaviour in Tutan.Messages. Calls DrainQueues() for both buses in LateUpdate. Auto-instantiated at BeforeSceneLoad with zero configuration; define TUTAN_MESSAGES_NO_AUTO_HOST to suppress the auto-spawned host and own the drain loop yourself.

MessagesHost class
method
void LateUpdate()
Calls EventBus.DrainQueues() and CommandBus.DrainQueues(). Override or detach if you need a different drain cadence.
MessagesBootstrap static
method
[RuntimeInitializeOnLoadMethod] static void Bootstrap()
Creates a hidden persistent [MessagesHost] GameObject at BeforeSceneLoad so both buses are drained every LateUpdate with no setup. Define TUTAN_MESSAGES_NO_AUTO_HOST to skip spawning the host and drive draining yourself. Command handlers are bound explicitly at your composition root via CommandBus.Install — there is no reflection-based auto-install.

MessagesInstrumentation

Static editor-only diagnostics surface in Tutan.Messages. All hooks gated behind [Conditional("UNITY_EDITOR")] and [Conditional("TUTAN_MESSAGES_DEBUG")] — stripped from release player builds.

MessagesInstrumentation static
field
bool Enabled
Master switch. When false every instrumentation hook short-circuits on the first branch (cost: one bool check per Publish). While true, every Publish/Enqueue record carries the boxed payload (one boxing allocation per record) — payload capture is not a separate switch. The Messages Console sets this automatically while the window is open.
method
Record[] Snapshot()
Returns a copy of the ring buffer. Allocates — keep off the hot path. Each record exposes Bus, Op, MessageType, frame, and timestamp.

EventReference / CommandReference

Serializable wrappers in Tutan.Messages that let designers pick a message type and edit its payload from the Inspector. Not for runtime hot paths — publishing involves JSON deserialization, Activator.CreateInstance, and boxing the struct before it is dispatched through the non-generic PublishBoxed seam (one unbox inside the channel). Message structs authored through a reference must be marked [Serializable] — the payload round-trips through JsonUtility, and a struct without the attribute silently keeps its default values.

EventReference serializable
method
void Publish()
Synthesizes the selected IEvent struct from inspector-edited fields and dispatches it via EventBus. Boxes the struct and dispatches it through the non-generic PublishBoxed seam (one unbox inside the channel).
CommandReference serializable
method
void Publish()
Same as EventReference.Publish but dispatches through CommandBus. Constrained to ICommand types in the inspector dropdown.

The inline editor renders each field with its matching native UI-Toolkit control: int, long, float, double, bool, string, any enum, Vector2/Vector3/Vector4, Vector2Int/Vector3Int, Color, and Quaternion (edited as euler angles). Other types fall back to a disabled "unsupported type" label. Every field is authored explicitly — including a field named Timestamp; the reference publishes exactly the values you enter, with nothing populated implicitly at publish time.

[EventType] / [CommandType] attributes

Parameterless attributes that decorate a string field so the Inspector renders it as a dropdown of message types, storing the selected AssemblyQualifiedName. The base-type filter is baked in; the runtime field type and storage format are unchanged from the previous parameterized [MessageType].

EventTypeAttribute attribute
usage
[EventType] public string eventType;
Dropdown of all concrete IEvent types in loaded assemblies.
CommandTypeAttribute attribute
usage
[CommandType] public string commandType;
Dropdown of all concrete ICommand types in loaded assemblies.
