API Reference

AppHost

All types live in namespace Tutan.Hosting. AppHost builds and installs Container at BeforeSceneLoad. It removes every service when the application quits, and starts from an empty container when Play Mode exits in the Editor.

AppHost static class
prop
ArchitectureContainer Container { get; }
The container the host builds, populated from SubsystemRegistration installers.
method
Task<Result<Unit>> WaitForInstallAsync()
The install outcome, the same task for every caller. A success once every service has installed; a failure that carries the first error otherwise, or AppHost has not initialized yet. before BeforeSceneLoad. A programmer error faults the task.

ArchitectureContainer

Registers services by layer and as Utilities, checks every constructor dependency against LowyTopology, and installs and removes them in dependency order. Every registration method returns the container, so calls chain.

ArchitectureContainer sealed class
method
AddManager<T>() / AddManager<TDefining, TImpl>()
Registers a Manager, by its concrete type or under a defining type. The concrete type carries [Manager].
method
AddEngine<T>() / AddEngine<TDefining, TImpl>()
Registers an Engine. The concrete type carries [Engine].
method
AddResourceAccess<T>() / AddResourceAccess<TDefining, TImpl>()
Registers a ResourceAccess. The concrete type carries [ResourceAccess].
method
AddResource<T>() / AddResource<TDefining, TImpl>()
Registers a Resource. The concrete type carries [Resource].
method
AddUtility<T>() / AddUtility<TDefining, TImpl>()
Registers a Utility. The concrete type carries no layer tag. Any service may depend on it, and it may depend only on other Utilities.
method
T Resolve<T>()
The singleton registered under T, once the install has succeeded. For handing a Manager to a Client; services receive their dependencies through their constructors.

The Add… constraints are T : class, IHostedService and TImpl : class, TDefining, IHostedService, and Resolve<T> asks only T : class, because a defining type need not implement IHostedService. A layered registration requires the matching layer tag on the concrete type or its assembly, and a Utility requires none; a mismatch fails the install.

Throws InvalidOperationExceptionWhen
Any Add… methodThe defining type is already registered, or the build has started

Every other problem is a Result A missing or wrong tag, an unregistered dependency, a forbidden edge, a cycle or a failed install comes back from AppHost.WaitForInstallAsync() as a failed Result with a named error. See Wiring & Enforcement for every message.
